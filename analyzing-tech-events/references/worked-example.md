# 完整范例：OpenManus 开源事件走通全流程

> 本范例演示每个阶段产出的**形状与深度标准**（有删节，非全文）。事件为 2025 年 3 月真实事件；范例中的细节基于当时的公开报道，作为教学示例使用前应重新核实。

## 事件背景（P0）

- 研究对象：OpenManus（开源 agent 框架）
- 触发事件：商业 agent 产品 Manus 发布并爆红后数小时内，MetaGPT 社区开发者宣布完成开源复刻并发布到 GitHub
- 事件类型：开源（竞品复刻型）
- 事件时长：当时 < 7 天 → 机制分析以源码审读为主，实测为辅

## P1 信噪比体检（节选）

**信源清单**：OpenManus 官方 README 与推文（一手）、MetaGPT 团队技术博客（一手）、多家科技媒体报道（多为转述同一篇首发稿，按一个信源计）、GitHub 指标（一手数据）。

**炒作信号核对**（8 项清单）：命中 2 项——#1 star 增速与 issue 使用反馈背离（当时 star 破万但真实使用报告稀少）；#4 无第三方复现（发布 < 72 小时，属正常）。→ **信噪比：中高**。

**反方声音**（找到 2 条）：有开发者指出 OpenManus 是「框架骨架」而非 Manus 全能力复刻，executa 层能力差距大；有评论认为其爆红是「占位卡位」而非工程完成度。→ 反方声音已收录进动机审计证据。

## P2 机制拆解（节选）

**组件判断表**（§6 模板，摘要）：

| 组件 | 判断 | 新原语/新编排 |
|------|------|--------------|
| 规划 | 外置 prompt 状态机 | 新编排 |
| 工具调用 | 标准浏览器/代码/文件工具集 | 新编排 |
| 沙箱 | Docker 隔离，常规方案 | 新编排 |
| 底层模型 | 依赖 Claude 等第三方模型 | 依赖项 |

结论：**工程复刻，无新原语**——其价值在速度与开源卡位，不在技术突破。（证据等级：B，源码审读；未实测，判断降级）

**Why Now**（§5）：使能线（agent 编排框架在 2024 下半年成熟，复刻的工程成本已降到「数小时」量级）+ 需求线（Manus 邀请码饥饿营销制造了巨大的未满足需求窗口）。两条线同时阶跃 → 技术节点为真。

**历史基准**（§11）：类比 2023 年 AutoGPT 爆红（宣传远超可用性）与各「XX 平替」案例；基准比率：爆红复刻类项目 12 个月内维持头部活跃的不足三成。**类比失效点**：OpenManus 背靠 MetaGPT 已有社区与工程团队，起点显著高于匿名复刻。

## P3 动机审计（节选）

**ACH 矩阵**（§4，摘要）：

```
证据＼假设                | A 社区占位卡位 | B 纯理想主义 | C 流量引流 | D 其他
数小时即发布（非仓促拼凑） |       C        |      I      |     C     |  —
背靠已有框架团队          |       C        |      I      |     —     |  C
MIT 许可、无商用限制      |       C        |      C      |     —     |  —
同步发布技术博客          |       C        |      C      |     I     |  —
```

结论：**A（社区占位卡位，给 agent 生态定开源参照系）置信度高**；B 被淘汰（纯理想主义项目通常不抢发布时间点）；C 部分存留（流量对后续商业化无害）；无法区分 A 与 D 的部分：是否为后续商业产品铺路——区分信号：未来 6 个月是否出现商业化公告。（证据等级：B/C）

## P4 冲击推演（节选）

**利益相关方地图**（摘要）：

| 相关方 | 升/贬 | 具体损益 |
|--------|------|---------|
| Manus（闭源） | 贬 | 「邀请码壁垒」叙事被免费开源对冲；神秘感是其核心资产 |
| MetaGPT 社区 | 升 | 证明工程响应速度，获得 agent 生态话语权 |
| agent 中间层 SaaS | 贬 | 「agent 能力」进一步被商品化，纯壳产品承压 |
| 云厂商 | 升 | 开源框架的托管需求 |
| 开发者 | 升 | 门槛降低，可直接魔改学习 |

**二阶传导链**：「Manus 闭源造势 + OpenManus 数小时开源复刻（一阶）→ agent 层的工程复刻成本被证明趋近于零，纯体验类 agent 产品的溢价逻辑失效，竞争焦点转向底层模型能力与数据回流（二阶）→ 评测体系、垂直场景数据、托管基础设施成为新的涨价要素（三阶）」。**最可能的应对**：Manus 类产品加速筑数据与分发护城河，而非功能对垒。

## P5 前景押注（节选）

**2×2 场景**（不确定性 1：社区能否维持工程投入；不确定性 2：Manus 是否开放部分能力）：

| 情景 | 概率 | 触发信号 |
|------|------|---------|
| 持续迭代的生态标准件 | 45% | 月度 release 稳定、外部贡献者占比上升 |
| 发布即巅峰的烟花 | 30% | 3 个月后 commit 断崖 |
| 被 Manus 开放策略收编 | 15% | Manus 官方开源组件 |
| 分叉混战 | 10% | 出现 2+ 活跃分叉 |

**可证伪预测**（§10 格式）：
1. 时间窗 3 个月：若 OpenManus 月 commit 数跌破 50 且无新 release → 「持续迭代」情景作废，届时公开修正本报告判断。
2. 时间窗 6 个月：若 Manus 宣布任何形式的开放权重/API 免费层 → 本报告「闭源造势」叙事线作废。
