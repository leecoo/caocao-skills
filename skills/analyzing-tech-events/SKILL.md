# 新技术事件深度分析（Analyzing Tech Events）

## 概述

一个全新 IT 技术事件发生时，传统"从诞生写到当下"的深研方法会失灵：对象没有自身历史可挖，竞品格局未成形，全网信息嘈杂且真假难辨。本方法把分析重心从"对象处在什么位置"换成五个事件问题：

**它到底是什么（机制）→ 为什么发生在现在（时机）→ 释放方图什么（动机）→ 谁受损（冲击）→ 接下来会怎样（押注）**

核心原则：**先去魅，再审动机，再推传导，最后押注。每一步结论必须标证据等级，每一条预测必须可证伪。**

产出：一份 8,000-15,000 字的深度报告（Markdown + PDF）。

## 何时使用 / 何时不用

**用：**
- 明星项目/模型/框架刚开源，需要深度判断
- 重大发布、关键融资并购、明星项目分叉刚刚发生
- 全网都在讨论同一个新事件，需要比别人深一层的分析
- 用户说「深度分析XX事件」「XX开源了怎么看」「研究一下这个新项目」

**不用：**
- 对象已有多年历史、竞争格局成形 → 应做对象全史 + 竞品横比 + 综合判断的常规深研
- 用户只要名词解释或概念科普
- 不含分析判断的纯写作任务

## 流程总览

| 阶段 | 回答的问题 | 必做产出 |
|------|-----------|---------|
| P0 对象确认 | 分析什么？事件发生多久了？ | 分析计划 |
| P1 信噪比体检 | 我拿到的信息可信吗？ | 炒作信号评分 + 反方声音清单 + 信源清单 |
| P2 机制拆解 | 真突破还是新组合？为什么是现在？ | 组件判断表 + Why Now 结论 |
| P3 动机审计 | 释放方图什么？ | ACH 矩阵 + 动机判断（带置信度） |
| P4 冲击推演 | 谁受益谁受损？竞争焦点移到哪？ | 利益相关方地图 + 二阶传导链 |
| P5 前景押注 | 接下来会怎样？ | 2×2 情景 + 可证伪预测 |
| P6 报告成稿 | 怎么交付？ | 七章报告 + PDF |

**必须联网搜索**，方法质量取决于信息丰富度。方法工具细节全部在 `references/method-library.md`（下称「方法库」），按各阶段标注的章节号查阅。写作风格遵循 `references/style-guide.md`。完整走通全流程的范例见 `references/worked-example.md`。

## P0 对象确认

1. **研究对象**：具体项目名/技术名/事件名
2. **事件类型**：开源、重大发布、融资、并购、分叉、标准之争
3. **事件发生多久了**（决定 P2 的验证策略）：
   - < 7 天：机制分析以实测 + 源码审读为主，第三方口碑尚未形成
   - 7 天 – 3 个月：可补充早期第三方复现、社区口碑
   - > 3 个月：本方法仍适用，但应同时考虑常规深研方法
4. **用户动机与特别关注点**：为什么要分析它？有没有指定深挖方向？已明确则不追问，直接开始。

---

## P1 信噪比体检（先于一切分析）

按方法库 §1–§2 执行。这一步过滤掉的噪音，决定后面四步的成败。

1. **信源分级与循环印证检查**：一手来源（官方博客、GitHub Release Notes、创始人公开发言）> 权威媒体原创报道 > 转载聚合。多家媒体转述同一篇原始报道，只能算一个信源。
2. **炒作信号清单**：8 项逐项核对（star 增速与 issue 活跃度背离、demo 视频剪辑痕迹、「改变一切」措辞密度、依赖特定 prompt 才能复现等），给出**信噪比定级：高/中/低**，定级写入报告。
3. **强制反方信源**：至少收集 **2 条**质疑或批评声音（Hacker News、Reddit、V2EX、技术社区讨论、竞方工程师评价、安全研究者分析）。**找不到反方声音本身就是最大警讯，必须作为独立发现写进报告，不允许默默跳过。**
4. **诚实标注**：搜不到的信息一律标注「暂缺」，绝不编造，绝不猜测填充。

---

## P2 机制拆解

按方法库 §5–§6、§11 执行。回答两个问题：

1. **真突破还是新组合**（第一性原理组件化）：把技术还原为不可再分的组件，逐项判断是「新原语」还是「已有组件的新编排」。`< 7 天` 的新事件优先实测验证。
2. **Why Now**：为什么不是三年前、不是三年后？找到成本曲线、模型能力、使能技术、市场需求四条线的交点。答不出 Why Now 的事件，通常只是营销节点而非技术节点。

**条件实测（硬规则）**：
- 环境允许 → 亲手设计 **3–5 个刁钻但真实**的任务跑一遍（避开 demo 演示过的路径），「宣传与实测的差距」写进报告；
- 环境不允许 → 在报告中显式标注「**未实测，本部分判断降级**」，并说明判断基于源码审读还是二手报道；
- **禁止**把官方 demo、README 截图、他人的复现结果当作自己的实测。

3. **历史基准**：找 2–3 个历史同类事件做类比，给出基准比率（类似事件中多少比例达成了宣传效果），并**明确写出本次类比失效的地方**。

---

## P3 动机审计

按方法库 §3–§4 执行。核心问题：**释放方为什么免费送给你 / 为什么现在发布 / 为什么用这种方式发布？**

1. 列出 **2–4 个竞争性动机假设**（动机清单：抢标准、众包工程、商业化漏斗、商品化互补品、人才声誉、数据获取……）；
2. 画 **ACH 矩阵**：用 P1–P2 收集的证据逐条检验每个假设，标记一致/矛盾，淘汰被证据压制的假设；
3. 输出：最可能动机 + **置信度** + 被排除假设及排除理由 + 无法区分的假设（诚实列出）。

红线：叙事最顺 ≠ 证据最硬。跳过 ACH 直接写动机结论是本方法最常见错误。

---

## P4 冲击推演

按方法库 §7–§8 执行。这一层是「事件分析」区别于「对象分析」的核心价值。

1. **利益相关方地图**：开源方/释放方、闭源巨头、中间层（做同类能力的 SaaS/工具商）、云厂商/算力方、开发者、最终用户，逐一方回答「此事让它升值还是贬值」；
2. **「谁受损」优先于「谁受益」**——受损方的应对，往往就是下一个故事线；
3. **二阶传导链**：一阶（门槛降低人人可用）→ 二阶（差异化消失后竞争焦点移到哪）→ 三阶（什么要素会涨价）。**每一环必须落到具体玩家的具体损益**；
4. 红线：禁止「行业会越来越好」「这是一次重大变革」式无传导链的空话。

---

## P5 前景押注

按方法库 §9–§10 执行。

1. **2×2 场景规划**：找出当前**两个最关键的独立不确定性**，构造四象限情景，每个情景配：概率（合计 100%）、触发信号（可观察的领先指标）；
2. **可证伪预测**：写下 2–3 条预测，每条必须含四要素：**时间窗 + 观察指标 + 阈值 + 证伪条件**。
   - 合格示例：「6 个月内，若该项目 commit 月度数跌破 50 且官方无商业化公告，则『商业化漏斗』动机假设被证伪」
   - 不合格示例：「它将继续快速发展」（无时间窗、无指标、无证伪条件，等于没有预测）

---

## P6 报告成稿

**七章结构，缺一不可**（每章是 REQUIRED 章节）：

```
# [事件名]深度分析：[一句话判断]
> 分析时间：XXXX-XX-XX | 事件类型：XX | 信噪比：高/中/低

一、结论前置          三句话：它是什么 / 释放方为什么 / 接下来会怎样
二、信噪比体检        炒作信号评分 + 反方声音（含「未找到反方声音」警讯）+ 信源清单
三、机制拆解          组件判断表 + 实测结果或降级声明 + Why Now + 历史基准
四、动机审计          ACH 检验过程 + 动机判断（置信度）+ 被排除假设
五、冲击推演          利益相关方地图 + 二阶传导链（谁受损优先）
六、前景押注          2×2 四情景 + 可证伪预测清单
七、方法附录          信息来源（URL+访问时间）+ 证据分级声明 + 本次分析的局限性
```

**字数与配比**：全文 8,000–15,000 字。参考配比——机制 25% / 动机 20% / 冲击 30% / 前景 15% / 其余 10%。字数服务密度：8,000 字扎实好过 15,000 字注水。

**证据分级声明**（放在第七章，每章结论标注等级）：
- **A 级**：亲手实测；**B 级**：源码/文档/一手材料审读；**C 级**：可信二手报道；**D 级**：推测（必须显式标注「我的判断是」）。

**交付物：PDF 优先，Markdown 回退**：

默认交付 **PDF**（排版正式的报告）。流程与回退规则：

1. 先完成 Markdown 稿 `[事件名]_深度分析报告.md`（第一个 `# 标题` 自动用作 PDF 封面标题；`> 分析时间：… | 事件类型：… | 信噪比：…` 会被提取到封面）；
2. 尝试生成 PDF：
   ```bash
   python <skill目录>/scripts/md_to_pdf.py 报告.md 报告.pdf --title "报告标题"
   ```
   依赖缺失时先尝试安装：`pip install weasyprint markdown`。**安装最多尝试 1 次，失败即走回退，不要反复尝试。**
   **Windows 特别提示**：WeasyPrint 依赖 GTK 运行时（gobject/pango/cairo DLL）。若本机无 GTK3-Runtime，即使 pip 装上 weasyprint 导入也会失败——探测到缺 GTK 时直接回退 Markdown，不要折腾安装（GTK 属系统级安装，超出常规权限）。
3. **回退规则**——出现以下任一情况，改为交付 Markdown 文件并在结尾说明原因，Markdown 稿的七章结构必须完整：
   - weasyprint / markdown 依赖无法安装（无网络、无权限）；
   - 转换报错且一次修正尝试后仍失败；
   - 系统缺中文字体导致 PDF 乱码且无法解决；
   - 用户明确只要 Markdown。

无论交付 PDF 还是 Markdown，Markdown 源稿都保留在工作目录，便于后续修改重排。

## 红线（任何一条都不允许突破）

1. **编造**：搜不到就写「暂缺」。编造团队背景、动机、数据是本方法的第一死罪。
2. **假装实测**：没有亲手跑过就不能写「实测发现」。环境不允许就声明降级。
3. **不可证伪的预测**：没有时间窗+指标+阈值+证伪条件的「预测」不许写。
4. **反方声音缺失不标注**：找不到批评者必须作为警讯写进报告。
5. **AI 味表达**：style-guide 中的绝对禁区清单适用于全文。

## 常见错误（借口对照表）

| 借口 | 现实 |
|------|------|
| 「全网都在说X，X 肯定是真的」 | 循环印证。转发链只能算一个信源 |
| 「官方 demo 效果好，等于实测过了」 | demo 是开发者挑过的最好路径，不是实测 |
| 「动机很明显是X，不用验证了」 | 叙事最顺 ≠ 证据最硬。ACH 矩阵必须过一遍 |
| 「时间紧，反方声音之后补」 | 没有反方声音的分析不能发布；实在找不到就标注警讯 |
| 「预测写模糊点永远不会错」 | 不可证伪的预测等于没有预测，且透支公信力 |
| 「翻了一下仓库/看了代码」（实际没做） | 场景里没做过的调查不许写。做了什么就写什么，没做就标注 |
| 「篇幅长显得有深度」 | 字数服务密度。删掉不改变任何判断的段落 |

## 红旗——出现任何一条，停下来回到对应阶段

- 正在写「这是行业的重大转折点」，但给不出传导链 → 回 P4
- 引用的每个信源都指向同一篇原始报道 → 回 P1
- 动机章节已经开写，但 ACH 矩阵还没画 → 回 P3
- 预测清单里没有一条能被证伪 → 回 P5
- 「未实测」的部分正在使用确定性语气 → 降级或补测

## 质检清单（交付前逐项自检）

- [ ] 每个竞争性动机假设都被证据检验过，而非选了叙事最顺的？
- [ ] 至少 2 条反方声音被收集并写进报告？没找到反方是否已作为警讯标注？
- [ ] 实测结论来自亲手跑的结果？未实测处标注了降级？
- [ ] Why Now 有明确回答？
- [ ] 二阶传导链落到具体玩家的具体损益？
- [ ] 每条预测含时间窗+指标+阈值+证伪条件？
- [ ] 每章结论标了证据等级（A/B/C/D）？
- [ ] 「暂缺」标注诚实？无编造？
- [ ] 七章结构完整？字数 8,000–15,000 且密度合格？
- [ ] 无 AI 味绝对禁区表达？
- [ ] 信息来源带 URL 和访问时间？
